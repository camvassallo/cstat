# Exact pins, not floors (issue #222). LightGBM's fitted trees depend on the
# library version as well as on the data, so a floor pin means the same frame
# can produce a different model on another machine or after an unrelated
# `pip install -U`. That undoes the reproducibility the deterministic frame
# ordering buys, and it makes a model diff unreviewable — you cannot tell a
# data change from a dependency bump.
#
# Pinned to what is currently installed in `training/.venv` — the environment
# the next retrain (#218) will run in, which is what makes that retrain's diff
# attributable. Not verified against the build environment of every artifact
# already in `training/models/`; several predate this pinning.
#
# Bumping any of these is a model-affecting change: retrain, and expect the
# artifacts to move.
