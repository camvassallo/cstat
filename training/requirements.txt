# Fully pinned, including transitive dependencies (issue #222).
#
# Why exact pins: LightGBM's fitted trees and the ONNX serializer both depend
# on library versions as well as on the data, so a floor pin means the same
# frame can produce a different artifact after an unrelated `pip install -U`,
# and a model diff can no longer distinguish a data change from a dependency
# bump. That is the whole guarantee #222 exists to establish.
#
# Why transitive too: the direct-only version of this file left 17 packages
# floating, including `protobuf` (which serializes the .onnx bytes) and
# `scipy` / `joblib` / `threadpoolctl` (under scikit-learn). Pinning only the
# names we import would have left the guarantee with a hole in exactly the
# layer that decides byte-level output.
#
# This is demonstrated, not theoretical. The same fitted model exported under
# two different dependency sets produced bit-identical predictions but
# different file bytes — the `opset_import` entries came out in a different
# order. Same model, different artifact.
#
# Targets Python 3.13 (see .github/workflows/ci.yml). Bumping any pin here is
# a model-affecting change: retrain, and expect the artifacts to move.
#
# To upgrade: bump the direct dependencies below, reinstall into a fresh
# venv, re-run `python test_frame_determinism.py`, and regenerate the
# transitive block with `pip freeze`.
